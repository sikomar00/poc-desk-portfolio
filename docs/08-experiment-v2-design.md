# 후속 실험 설계 (실험 전 동결 문서)

## 요약
v1 실험(07 문서)에서 드러난 사전의 약점을 고친 **사전 v2**가 정말 나아졌는지를, **처음 보는 질문 10개(보류 질문)** 로 확인합니다. 같은 실험에서 소급 시험으로 고른 **검증 방법 1과 3′** 가 새 질문에서도 쓸 만한지 **미리 정한 규칙으로** 평가합니다.

이 문서는 **실험을 돌리기 전에** 질문, 사전, 판정 규칙, 평가 코드를 고정하는 기록입니다. 아래 "동결 해시"의 파일이 바뀌면 평가 코드가 실행을 거부합니다.

| 질문 | 어떻게 답하나 |
|---|---|
| Q-A. 사전 v2가 v1보다 정확한가? 사전 문구 변경의 부작용은 없는가? | 표적 5문항과 대조 5문항으로 B1(v1) 대 B2(v2) 정확도 비교 |
| Q-B. 방법 1(교차 모델 불일치)과 3′(반복 4/5 미만 일치)가 새 질문에서 재현되는가? | 경보 정밀도와 검출률을 사전 규칙으로 판정 |

## 1. v1에서 v2로: 무엇을, 왜 바꿨나

v2는 **관찰된 실패 두 가지에만** 근거해 고쳤습니다. 다른 곳을 마음대로 고치면 무엇이 효과를 냈는지 알 수 없고, 이미 본 문제에 맞춰 과하게 고칠 위험도 있습니다.

| 지표 | 근거가 된 관찰 (07 문서) | v2 변경 (SQL은 주지 않음) |
|---|---|---|
| 환불률 | 두 모델 모두 3/20. "결제 완료"를 `status='PAID'`로 해석해 결제 후 취소를 빠뜨림 (5절 2번) | 분자·분모 모두 `paid_at`이 있는 주문 기준이며 `status`로 거르지 않음, `refund_type`별 환산을 컬럼 이름으로 명시 |
| 매출 | 같은 "결제 완료" 용어 사용 | "결제 완료는 `paid_at` 값이 있다는 뜻이며 `status`와 무관" 명시 |
| 유효 주문 수 | Q19에서 사전의 별칭을 무시(gpt-oss 0/5) (5절 3번) | 수식어 없는 "주문 수/몇 건"이 이 지표임을 명시, 별칭에 "주문 건수" 추가, 컬럼 대응 추가 |
| 객단가 | 분자·분모가 위 두 정의에 의존 | 두 정의를 컬럼 대응까지 그대로 따름을 명시, 별칭 추가 |
| 취소율 | 이미 대부분 맞음 | **변경 없음(대조군)** |

**v2가 주지 않는 것:** 계산 SQL, 정답 값, 질문별 힌트. 06 문서에서 정한 원칙(D-017)을 그대로 지킵니다. 프롬프트의 다른 부분도 v1과 동일하며 **사전 텍스트 하나만** 다릅니다.

## 2. 보류 질문 10개

v1의 20개 질문은 v2를 만들 때 실패를 이미 본 질문이라 평가에 쓰지 않습니다. 아래 10개는 v2를 만들 때 쓰지 않았고 v2 실행 결과도 아직 보지 못한 질문입니다. 골드 답은 SQL로 만든 값을 **파이썬으로 따로 다시 계산해 일치**함을 확인했습니다(`experiment/holdout.py`).

| ID | 질문 | 지표 | 구분 | 노리는 지점 |
|---|---|---|---|---|
| H01 | 1월과 2월 매출을 합치면 얼마야? | 매출 | 대조 | 새 기간 조합 |
| H02 | 2월에 판매한 것 중 환불로 나간 비중은? | 환불률 | **표적** | 새 별칭("비중"), 결제 후 취소 |
| H03 | 2~3월 환불률 알려줘 | 환불률 | **표적** | `status` vs `paid_at`, 새 기간 조합 |
| H04 | 1~2월 환불률은 몇 %야? | 환불률 | **표적** | 합계끼리 나누기, 새 기간 조합 |
| H05 | 2월에 주문 취소가 몇 퍼센트나 돼? | 취소율 | 대조 | 사전 변경 없음 |
| H06 | 1~2월 취소율은? | 취소율 | 대조 | 사전 변경 없음, 새 기간 조합 |
| H07 | 2~3월에 주문 하나당 평균 얼마 팔렸어? | 객단가 | 대조 | 새 별칭, 새 기간 조합 |
| H08 | 2월 객단가는? | 객단가 | 대조 | 분자·분모 정의 |
| H09 | 1월 주문 건수가 몇 건이야? | 유효 주문 수 | **표적** | 수식어 없는 "주문 건수" |
| H10 | 3월에 주문 몇 건 들어왔어? | 유효 주문 수 | **표적** | 수식어 없는 "주문 몇 건" |

- **표적 5개**는 v2가 고친 지점을 건드립니다. v2의 효과를 보는 문항입니다.
- **대조 5개**는 이미 맞히던 지표이거나 사전을 바꾸지 않은 지표(취소율)입니다. v2의 문구 변경이 **다른 곳을 망가뜨리지 않았는지(회귀)** 확인합니다.

> 📘 **개념 학습 — 회귀(regression) 확인**
> 고치면서 다른 곳이 나빠지는 일을 회귀라고 합니다. 환불률 문구를 고쳤더니 취소율이나 매출 답이 나빠질 수도 있습니다. 그래서 고친 곳과 고치지 않은 곳을 따로 평가하고, 고친 곳이 좋아졌더라도 고치지 않은 곳이 나빠졌다면 개선이라고 쓰지 않습니다.

**한계(숨기지 않기):**
- 질문 10개 중 **5개(H01, H03, H04, H06, H07)만 새 기간 조합**이고, 나머지 5개는 v1 질문과 같은 계산을 다른 표현으로 물은 것입니다. 표현에 대한 일반화는 보지만 완전히 새로운 계산은 아닙니다. (가능한 단일 월·지표 조합은 v1이 이미 소진했습니다.)
- 질문을 내가 썼습니다. v2를 쓴 사람과 같아서 v2에 유리한 표현이 섞였을 수 있습니다(06 문서와 같은 한계).

## 3. 실험 설계

| 항목 | 내용 |
|---|---|
| 조건 | **B1** = 사전 v1 / **B2** = 사전 v2. 프롬프트의 다른 부분은 동일. (조건 A는 이미 측정했으므로 넣지 않음) |
| 모델 | `openai/gpt-oss-20b`, `nvidia/nemotron-3-super-120b-a12b` (D-021) |
| 호출 | 10질문 × 5회 × 2조건 = 모델당 100회, 총 200회. 온도 0.7, 최대 토큰 4096 (D-022) |
| 호출 순서 | 두 조건을 섞어 실행 (고정 시드) |
| 기록 | `experiment/runs/*.jsonl`. 첫 줄에 질문·사전 해시가 남고, 평가기가 동결 내용과 같은지 확인 |
| 채점 | 06 문서와 동일한 허용 오차 |
| 서비스 장애(`llm_error`) 처리 | 모델의 오답으로 세지 않는다. 같은 `--run-id`로 다시 실행하면 그 호출만 재시도하고, 끝내 실패하면 분석에서 **제외하고 개수를 보고**한다(D-027). v1 실험에서는 장애 호출이 0건이었음 |

## 4. 사전 지정 판정 규칙 (실행 전 고정)

### Q-A. 사전 v2가 v1보다 나은가
| 판정 | 조건 |
|---|---|
| **개선(회귀 없음)** | 표적 정확도가 B1 대비 **+20%p 이상**이고, 대조 정확도 변화가 **−5%p 이상**(−5%p보다 더 나빠지지 않음) |
| 개선되었으나 회귀 | 표적 +20%p 이상이지만 대조가 −5%p보다 더 떨어짐 |
| 무개선 | 표적 개선이 **5%p 미만** |
| 불명 | 위에 해당하지 않음 |

판정은 모델 합산으로 내립니다(모델별 결과도 함께 표시). 일치율은 참고로만 보고하며 판정에 쓰지 않습니다(v1 판정은 이미 별도로 끝났으므로).

### Q-B. 검증 방법 1과 3′의 재현
- **방법 1:** 같은 질문·같은 회차에서 다른 모델의 값과 허용 오차 밖으로 다르면 경보.
- **방법 3′:** 한 모델이 같은 질문 5회 중 4회 이상 같은 값을 내지 못하면 그 질문의 5개 답 모두 경보.
- **주 평가 조건은 B1.** 소급 시험(07 문서 7절) 때와 오답 비율이 비슷해 비교할 수 있기 때문입니다. B2는 오답이 적어 표본이 모자랄 수 있어 참고로 봅니다.

| 판정 | 조건 |
|---|---|
| **재현됨** | 경보 정밀도가 기준선(전체 오답 비율)의 **1.5배 이상** 이고, 오답 검출률 **60% 이상** |
| 재현 실패 | 경보 정밀도가 기준선의 **1.2배 미만** |
| 불명 | 위 두 경우 사이 |
| 표본 부족 | 분석 대상 오답이 **10개 미만**이면 판정하지 않음 |

임계값은 소급 시험 결과(검출 73~79%, 정밀도 58~63%, 기준선 대비 1.7~1.8배)에서 **여유를 두고 낮춰** 잡았습니다(새 데이터에서는 낙관적 수치가 줄어들 것이므로).

## 5. 동결 해시

아래 파일이 실험 후에 바뀌면 안 됩니다. 평가 코드(`evaluate_v2.py`)는 실행 기록의 질문·사전 해시를 현재 파일과 비교하고, 다르면 평가를 중단합니다. (파일 SHA-256의 앞 16자리, 2026-10-19 동결)

| 파일 | 해시 |
|---|---|
| `experiment/questions_A_holdout.json` | `92506ce3ff8f9a26` |
| `experiment/kpi_dictionary_A.json` (v1) | `c7d92ac8cd0d79eb` |
| `experiment/kpi_dictionary_A_v2.json` | `0280eb893bbcfbac` |
| `experiment/evaluate_v2.py` (판정 규칙 포함, D-027 개정 후) | `0869a0581c480290` |
| `experiment/holdout.py` | `73413d2eb33a5bda` |
| `experiment/run_experiment.py` (프롬프트·채점·허용 오차) | `2b3182798665a4ba` |

> 📘 **개념 학습 — 보류 질문은 한 번만 쓴다**
> 시험 문제를 한 번 보고 나면 그 문제는 더 이상 새 문제가 아닙니다. 이 10개 질문은 v2를 **한 번** 평가하는 데만 쓰고, 결과를 본 뒤 사전을 다시 고쳐 같은 질문으로 재평가하지 않습니다. 더 고치고 싶으면 새 보류 질문을 따로 만듭니다.

## 6. 실행 순서 (직접 실행)

PowerShell에서 키를 설정한 창이어야 합니다. 먼저 **작은 테스트**를 하고 본 실험으로 갑니다.

```powershell
# 1) 스모크 테스트: 4회만, 동시 2개
python C:\realDefinition\experiment\run_experiment.py --suite holdout --model openai/gpt-oss-20b --limit 4 --workers 2

# 2) 본 실험: 모델마다 100회 (동시 8개). 응답이 한 번에 40~110초, 가끔 수 분 걸려 모델당 20~30분 예상
python C:\realDefinition\experiment\run_experiment.py --suite holdout --model openai/gpt-oss-20b --workers 8
python C:\realDefinition\experiment\run_experiment.py --suite holdout --model nvidia/nemotron-3-super-120b-a12b --workers 8

# 3) 사전 지정 평가
python C:\realDefinition\experiment\evaluate_v2.py
```

스모크 테스트 기록은 본 실험과 **다른 실행 ID**로 남으므로 섞이지 않습니다. 평가기는 모델당 가장 최근의 holdout 기록 1개를 읽으므로, 본 실험은 **각 모델당 한 번만** 끝까지 실행하세요(중간에 끊기면 같은 `--run-id`로 이어서).

## 6-1. 스모크 테스트 결과 (본 실험 전, 2026-10-19)

`gpt-oss-20b`로 4회(`--limit 4`) 실행해 **동작만 확인**했습니다(`experiment/runs/20261019-210429-gpt-oss-20b.jsonl`).

| 확인 항목 | 결과 |
|---|---|
| 질문·사전 해시가 동결 내용과 일치 | 일치 |
| 종료 사유, 호출 실패 | 4회 모두 `stop`, `llm_error` 0건 |
| 응답 시간 | 56초, 96초, 110초, **336초**(시간 초과 후 재시도로 성공한 것으로 추정) |
| 4회 중 SQL 오류 | 1회(`aggregate functions are not allowed in the GROUP BY clause`, 모델 쪽 SQL 오류) |

- **정답 여부는 확인하지 않았습니다.** 상태·해시·응답 시간만 보았습니다. 이 4개 기록은 본 실험과 **다른 실행 ID**라서 본 실험 평가에 들어가지 않습니다(평가기는 모델당 가장 최근 holdout 기록 1개만 읽음).
- 336초 호출은 본 실험에서 호출이 끝내 실패하는 경우가 생길 수 있다는 신호였습니다. 이 때문에 D-027로 장애 호출 처리 규칙을 **본 실험 전에** 추가했고(위 설계 표 참조), 동결 해시도 그에 맞게 갱신했습니다.

## 7. 한계와 검정력

| 한계 | 영향 |
|---|---|
| 표적 5문항 × 5회 × 2모델 = 조건당 50회지만, 같은 질문 5회는 독립이 아니므로 **실제 독립 단위는 질문 5개** 수준 | 신뢰구간이 넓다. +20%p 같은 차이도 우연일 수 있다. 판정이 "불명"이 될 가능성이 크다 |
| 모델 2개, 온도 0.7 | 일반화 제한 |
| 질문 일부가 v1과 같은 계산을 다른 표현으로 물은 것 | 새로운 계산에 대한 일반화는 약함 |
| 방법 1과 3′의 임계값이 소급 시험에서 고른 것 | 이번 평가가 처음으로 사전 지정된 검증이다 |
| 오답이 적은 B2는 방법 평가의 표본이 부족할 수 있음 | 주 평가는 B1로 정해 둠 |
| 모의(MOCK) 실행으로 평가 코드 동작만 확인 | 코드 오류 가능성은 줄었지만 실제 모델 출력 형식으로는 아직 시험하지 못함 |
