# 하나의 Postgres에 스키마 3개(demo·personal·app)로 나눈다

합성 주문(공개), 실제 가계부(본인 전용), 지표 정의·원장·실행 기록을 한 Supabase 프로젝트 안의 `demo`·`personal`·`app` 스키마로 나눈다. 프로젝트를 둘로 나누는 편이 더 안전하지만, 무료 플랜에서 관리할 대상이 늘고 지표 정의가 두 데이터셋을 함께 다뤄야 해서 스키마 분리와 역할별 권한으로 막는다.

## Considered Options
- 한 스키마에 전부(`dataset` 컬럼으로 구분): RLS 한 번의 실수로 실제 데이터가 공개 읽기에 노출될 수 있어 기각.
- 프로젝트 2개(공개용·개인용): 격리는 가장 강하지만 정의·원장을 공유하기 어려워 기각. 가계부를 공개 데모와 완전히 분리해야 하는 상황이 오면 다시 검토.
