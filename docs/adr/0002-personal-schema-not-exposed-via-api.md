# 가계부 스키마(personal)는 Supabase API에 노출하지 않는다

실제 가계부는 앱 서버만 읽기 전용 DB 역할로 직접 접속해 조회하고, 서버가 본인 세션을 확인한다. 일반적인 Supabase 방식(브라우저가 RLS를 믿고 API로 직접 조회)과 다르지만, LLM이 만든 SQL이 실행되는 경로라서 "인터넷에서 닿는 길 자체를 없애는" 쪽을 택했다. RLS(`owner_id`)는 두 번째 방어선으로만 켜 둔다.

## Consequences
- 브라우저에서 가계부를 직접 조회하는 기능은 만들 수 없다. 모든 조회는 서버를 거친다.
- 서버가 본인 확인에 실패하면 `personal`을 읽는 연결 자체를 열지 않는다.
