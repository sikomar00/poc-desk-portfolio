## 2. 잘한 것

1. **판정 기준을 결과 전에 고정하고 지켰습니다.** 정확도가 +52~65%p 올라 "대성공"이라고 쓸 수 있었지만 일관성 기준에 미달해 "불명"이라고 썼습니다. 이 한 번의 선택이 나머지 모든 결과의 신뢰도를 정했습니다.
2. **고치기 전에 결과를 보호했습니다.** 사전의 약점을 발견하고도 같은 질문으로 다시 재지 않고, 새 질문 10개를 따로 만들어 평가했습니다.
3. **고친 곳과 고치지 않은 곳을 따로 평가했습니다.** 덕분에 환불률을 고쳤더니 취소율이 영향을 받는 **번짐**을 발견했습니다.
4. **이중으로 계산해 확인했습니다.** 정답은 SQL과 파이썬으로 각각 계산해 비교했고, 매출은 원장, 가계부는 앱 합계로 외부 출처와 대조했습니다.
5. **외부 사실을 확인했습니다.** API 호출 조건을 공식 문서로 확인하고, 확인하지 못한 수치(공식 한도, `seed` 지원)는 사실처럼 쓰지 않았습니다.
6. **실데이터를 안전하게 다뤘습니다.** 원본은 로컬 전용 폴더에 두고, LLM에는 테이블 구조와 사전만 보냈으며, 공개 문서에는 집계만 기록했습니다.

## 3. 틀렸던 것과 고친 과정

| 실수 | 어떻게 알았나 | 교훈 |
|---|---|---|
| 정답표를 LLM 입력에 섞음 (조건 A가 정답을 베낄 수 있었음) | 모의 실행의 **프롬프트를 눈으로 읽다가** | 모델이 보는 모든 입력에 정답과 힌트가 없는지 점검하는 단계가 필요하다 |
| 테이블 주석에 정의 힌트("매출 제외 대상") | 같은 점검 | 통제하려는 변수 외에는 같아야 한다 |
| 환불률 오답을 "사전 문구가 모호해서"라고 해석 | 두 번째 모델 결과와 DB 재계산으로 반박됨 | 한 모델의 결과로 원인을 단정하지 말고, 가설은 데이터로 시험한다. 틀린 해석은 문서에서 정정한다 |
| "기준선의 1.5배" 판정 기준 | 결과 해석 중 최댓값 계산 | 비율 기준은 천장(상한)을 먼저 계산해 본다 |
| 서비스 장애가 오답으로 집계될 뻔함 | 스모크 테스트의 336초 응답 | 실행 전에 인프라 실패 처리 규칙을 정한다 |
| API 키를 대화창에 붙여 넣음 (두 번) | 노출을 인지하고 폐기·재발급 | 키는 창에 붙이지 말고 입력 프롬프트로만 입력한다. **노출된 키의 폐기 여부를 직접 확인할 것** |

## 4. 배운 개념 (내 말로 설명할 수 있어야 하는 것)

- **문제 정의**는 해결책이 아니라 "누가 무엇 때문에 곤란한가"를 쓰는 일이다.
- **KPI 사전**은 지표마다 계산식, 포함·제외, 기간 기준, 단위를 한 곳에 확정한 것이다.
- **정확도와 일치율은 다르다.** 항상 같은 오답을 내면 일치율은 100%, 정확도는 0%다.
- **사전 등록**: 결과를 보기 전에 판정 기준을 고정해야 어떤 결과도 성공으로 만들 수 없다.
- **보류 질문(홀드아웃)**: 개선에 쓰지 않은 질문으로만 개선을 평가한다.
- **회귀 확인**: 고친 곳과 고치지 않은 곳을 모두 평가한다. **번짐**이 그 예다.
- **대사**: 서로 독립된 출처의 숫자를 맞춰 본다. 정답 출처가 있으면 허용 오차는 0이 안전하다.
- **거짓 경보 vs 놓침**: 맞바꿈 관계이고 어느 쪽이 비싼지는 상황이 정한다. **정밀도는 기준선과 함께** 본다.
- **누수(leakage)**: 평가의 정답이나 힌트가 입력에 섞이는 것.

## 5. 한계에 대한 정직한 평가

- **이 실험으로 "KPI 사전이 효과가 있다"고 일반화할 수 없습니다.** 모델 2개, 온도 하나, 질문 30개, 합성 데이터 3개월입니다.
- 사전과 질문을 **같은 사람이** 작성해 사전에 유리한 표현이 섞였을 수 있습니다.
- 환불률과 유효 주문 수에서 남은 오류(두 모델이 같은 틀린 값을 반복)는 **원인을 진단하지 못했습니다.**
- "회귀"는 호출 3개 차이로 판정된 아슬아슬한 결과입니다.
- 번짐은 **가설**입니다. 오답 값 검증으로 일부 호출만 설명했습니다.
- **다루지 못한 것:** 앱의 AI 모드를 실제 모델로 호출해 보는 것(화면 앱 자체는 [12 문서](12-poc-desk-app.md)에서 구현), 실제 현업 인터뷰, 고객 환경 설치, ERP/CRM 연동, Tableau·ETL, 질문별 검색(RAG), 시맨틱 레이어 시험.
