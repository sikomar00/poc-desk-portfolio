# PRD — realDefinition

## 요약
요구 한 줄을 입력하면 **모호한 부분을 되묻고 → KPI 정의서를 확정하고 → 그 정의로 SQL을 만들어 실행하고 → 결과를 원장과 대사하고 → PoC 리포트(md)를 남기는** 웹앱. 목표는 "같은 질문에 같은 숫자, 그리고 그 숫자를 믿을 근거".

## 1. 배경과 목표

| 구분 | 내용 |
|---|---|
| 문제 | [문제 정의서](01-problem-definition.md) 참고 |
| 목표 G1 | 같은 질문에 대한 숫자 일치율 향상 (H1) |
| 목표 G2 | 정의서 필수 항목 누락 감소 (H2) |
| 목표 G3 | 틀린 SQL 결과를 사용자에게 보여 주기 전에 검출 (H3) |
| 비목표 | 자체 모델 학습, 고급 시각화, 다중 사용자·역할 구분(본인 1계정만), **실제 가계부의 공개 노출** |
| 범위 확장(2026-10-20) | 클라우드 DB(Supabase, 합성 데이터), 본인 로그인, 공개 데모 배포는 이제 범위 안이다(F10~F13, NF6~NF9). 실제 가계부(case B)는 로컬·본인 전용으로만 다룬다 |

> 📘 **개념 학습 — PRD는 "만들 것"보다 "만들지 않을 것"이 더 중요하다**
> 범위가 번지면 초보 프로젝트는 끝나지 않습니다. 비목표를 적어 두면 "이건 나중에"라고 말할 근거가 생깁니다.

## 2. 사용자

| 페르소나 | 설명 | 핵심 과제(JTBD) |
|---|---|---|
| 현업 정은(가상) | 영업기획 담당. SQL은 모름 | "이번 달 매출을 내가 믿을 수 있는 숫자로 받고 싶다" |
| 분석가 민수(가상) | BI 엔지니어 | "정의를 한 번에 확정해 재작업을 없애고 싶다" |
| 공개 방문자(면접관·채용 담당) | 설치 없이 주소만으로 접속, 로그인 없음 | "이 프로젝트가 뭘 증명하는지 2분 안에 눌러 보고 싶다" |
| 본인(운영자) | 로그인한 1계정. 실행 기록·리포트·라이브 AI 사용 | "면접에서 라이브로 시연하고 기록을 남기고 싶다" |

## 3. 기능 요구사항

우선순위: **M**ust(핵심) / **S**hould / **C**ould.

| ID | 기능 | 우선 | 수용 기준 (이게 되면 완료) |
|---|---|---|---|
| F1 | 요구 접수: 자연어 한 줄 입력 | M | 입력 후 정의서 초안 화면으로 이동 |
| F2 | 모호성 되묻기: 정의 필수 항목(계산식, 포함·제외, 기간 기준, 단위) 중 비어 있는 것을 질문으로 제시 | M | 필수 4항목이 모두 채워질 때까지 확정 버튼 비활성 |
| F3 | KPI 사전 저장·조회·버전 관리 | M | 확정한 정의가 저장되고 이전 버전과 비교 가능 |
| F4 | 정의 기반 SQL 생성(Text-to-SQL, KPI 사전 참조) | M | 생성 SQL이 사전의 정의를 그대로 반영(사전 없는 지표는 생성 거부) |
| F5 | 샘플 DB에서 SQL 실행 | M | 결과가 표로 표시, 실행 시간 기록 |
| F6 | 결과 대사(원장 합계와 비교) | M | 차이 0이면 통과, 아니면 경고와 차이 금액 표시 |
| F7 | PoC 리포트 md 내보내기 | S | 문제·정의·SQL·검증 결과·한계가 규격 양식으로 출력 |
| F8 | 일치율 실험 실행기(같은 질문 N회) | S | 조건 A/B의 일치율 표 출력 |
| F9 | 실패 사례 기록(오류, 원인, 조치) | S | 케이스별 로그가 md로 누적 |
| F10 | 로그인(본인 1계정, 가입 닫힘). 역할 구분은 제외 | S | 비로그인은 계산·정의 비교만, 로그인하면 실행 기록·리포트가 본인 것만 보임. 로그인 실패 이유가 화면에 표시됨 (구현) |
| F11 | 정의 비교: 같은 질문을 정의 N가지로 나란히 계산 | S | 매출 질문에서 정의 6가지의 값과 차이(원·%)가 보이고, 공식 정의가 원장과 일치하는지 표시됨 (구현) |
| F12 | 공개 데모 접근 규칙(같은 출처만, 비로그인 DB 쓰기 없음, 정의 저장 끔, 속도 제한) | M | 다른 출처 POST 403, 비로그인 정의 저장 403, 기록·리포트 401, 연속 요청 429 (구현) |
| F13 | 라이브 AI 모드는 로그인한 본인에게만 | S | 비로그인은 선택 불가·API 401, 본인은 실제 모델로 실행하고 대사 2건이 표시됨 (구현) |
| F14 | 방문자 AI 체험: 실험에서 기록한 실제 모델 SQL을 같은 안전 검사·대사로 재생 | S | 비로그인으로, 비용 0·키 불필요로, 정답·오답이 섞인 기록의 통과/경고를 보고 '녹화된 출력'임이 표시됨 (**제안, 미착수**, [Intent](../Intent.md) INT-006) |

## 4. 비기능 요구사항

| 항목 | 기준 |
|---|---|
| NF1 정확성 | SQL은 읽기 전용(SELECT만). 쓰기·삭제 구문 차단. DB에서도 읽기 전용 역할·5초 제한으로 이중 방어 |
| NF2 추적성 | 모든 숫자에 "어떤 정의 버전·어떤 SQL"이 연결됨 |
| NF3 재현성 | 같은 정의·같은 데이터면 같은 결과(로컬 SQLite와 Supabase에서 값이 같아야 함) |
| NF4 보안(비밀) | API 키·DB 비밀번호는 코드에 넣지 않고 환경 변수로 관리. 배포 환경에는 최소 권한 비밀만 등록 |
| NF5 개인정보 | 합성 데이터만 공개. 실제 가계부는 공개 앱·클라우드에 올리지 않음 |
| NF6 공개 보안 | 인터넷 공개 모드에서는 같은 출처만 허용, 비로그인의 DB 쓰기·정의 저장 차단, 속도 제한 |
| NF7 응답 시간 | 공개 주소에서 계산식 모드 첫 요청 ≈4초(콜드 스타트) 이후 ≈1초, 정의 비교 ≈2초, AI 모드는 서버 한도 60초 안 |
| NF8 비용 | 무료 플랜 안에서 운영. AI 호출 비용은 본인 키 사용량으로 제한(방문자에게 열지 않음) |
| NF9 시각 | 화면·기록 시각은 한국 시간(KST) |

## 5. 성공 지표

| 지표 | 정의 | 목표(초안) | 측정 방법 |
|---|---|---|---|
| 숫자 일치율 | 같은 질문 N회 중 동일 결과 비율 | A(사전 없음) 대비 B(사전 있음)가 유의하게 높음, B ≥ 90% | F8 |
| 정의 완결도 | 필수 4항목 중 채워진 비율 | 100% 확정 | F2 |
| 오류 검출률 | 의도적 오류 SQL 중 대사로 걸러낸 비율 | ≥ 80% | F6, 테스트 세트 10개 |

`[가정]` 위 목표 수치는 초기 추정이며 첫 실험 후 조정한다. 조정 시 사고 흐름 기록에 남긴다.

## 6. 데이터 (개요)
- 합성 `customers`, `products`, `orders`, `order_items`, `refunds` 5개 테이블(`demo` 스키마)과 정답표 `ledger`(`app` 스키마). 전체 구조와 로그인 엔터티는 [ERD](../erd.md)가 기준이다.
- 정의 충돌을 심어 둠: 부가세 포함 금액, 취소 주문, 부분 환불, 결제일 vs 주문일.
- 상세 설계는 05 데이터 설계에서 다룬다.

## 7. 리스크

| 리스크 | 영향 | 대응 |
|---|---|---|
| LLM이 사전에 없는 지표를 추측 | 틀린 숫자 | F4에서 사전 외 지표 거부 + F6 대사 |
