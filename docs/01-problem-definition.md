# 문제 정의서

## 요약
**현업이 같은 질문("이번 달 매출")을 해도, 지표 정의가 어디에도 확정돼 있지 않아 담당자·SQL·AI마다 다른 숫자가 나온다. 그래서 숫자를 믿지 못해 재작업과 신뢰 하락이 반복된다.**
같은 구조가 PoC 시작 단계에서도 나타난다. 성공 기준이 없는 채로 시작해 "됐는지 안 됐는지"를 판단할 수 없다.

## 1. 문제 진술 (Problem Statement)

| 항목 | 내용 |
|---|---|
| 누가 | 데이터 질문을 하는 현업 담당자, 숫자를 만드는 분석가·엔지니어 |
| 언제 | 보고서·대시보드를 만들거나 LLM에게 데이터를 물을 때, PoC를 시작할 때 |
| 무엇이 곤란한가 | 같은 질문에 서로 다른 숫자. 어느 쪽이 맞는지 판단 기준이 없음 |
| 지금은 어떻게 | 담당자 기억·메신저·엑셀 메모로 정의를 확인하고, 틀리면 다시 만든다 |
| 왜 중요한가 | 재작업 비용, 의사결정 지연, 특히 LLM 도입 시 **틀린 숫자를 자신 있게 답함** |

> 📘 **개념 학습 — 문제와 해결책을 섞지 않기**
> "KPI 사전 앱을 만든다"는 해결책입니다. 문제 정의에는 해결책 단어가 들어가면 안 됩니다. 해결책을 문제 속에 넣으면, 더 나은 해결책이 있어도 보지 못합니다. 판별법은 "이 문장에서 앱·기능 이름을 지워도 문제가 남는가?"입니다.

## 2. 이해관계자

| 역할 | 원하는 것 | 불안·고통 | 이 문서에서의 위치 |
|---|---|---|---|
| 현업 담당자 | 믿을 수 있는 숫자를 빠르게 | 숫자가 다르면 보고 못 함 | 주 사용자 |
| 분석가·BI 엔지니어 | 정의를 한 번에 확정 | 같은 정의를 매번 되묻고 재작업 | 주 사용자 |
| PoC 담당자 | 성공 기준을 시작 전에 합의 | 끝나고 "그래서 된 거야?"가 모호 | 부 사용자 |
| 고객 IT | 시스템·데이터 영향 최소화 | 권한·보안 | 제약 조건 |

## 3. 원인 분석 (5 Why, 간단판)

1. 왜 숫자가 다른가? → 계산 기준이 사람마다 다르다 (부가세, 취소, 기간 기준).
2. 왜 기준이 다른가? → 정의가 문서가 아니라 사람 머릿속에 있다.
3. 왜 문서가 없는가? → 프로젝트 시작 때 "정의 확정" 단계가 없고 바로 개발한다.
4. 왜 그 단계가 없는가? → 요구를 구조화해 되묻는 표준 절차(양식)가 없다.
5. 왜 LLM에서 더 위험한가? → LLM은 모르는 정의를 되묻지 않고 **추측해서 답한다**(환각).

**뿌리 원인(가설):** 정의가 확정·기록되기 전에 계산이 시작된다.

## 4. 가설과 검증 방법

| ID | 가설 | 검증 방법 | 상태 |
|---|---|---|---|
| H1 | 정의서 없이 LLM에게 묻는 것보다, KPI 사전을 함께 주면 같은 질문의 숫자 일치율이 오른다 | 같은 질문 20개를 두 조건에서 각 5회 실행, 일치율 비교 | [가정] 미검증 |
| H2 | 모호한 요구를 되묻는 양식이 있으면 확정되는 정의 항목 누락이 줄어든다 | 정의서 필수 항목 체크 누락 수 비교 | [가정] 미검증 |
| H3 | 결과 합계를 원장과 자동 대사하면 틀린 SQL을 사용자가 보기 전에 걸러낼 수 있다 | 의도적 오류 SQL 10개 중 잡아낸 수 | [가정] 미검증 |

> 📘 **개념 학습 — 가설은 "틀릴 수 있는 문장"이어야 한다**
> "AI가 도움이 된다"는 가설이 아닙니다. 맞고 틀림을 숫자로 가릴 수 없기 때문입니다. "일치율이 X%에서 Y%로 오른다"처럼 측정할 수 있어야 가설입니다.

## 5. 범위

| 포함 | 제외 (비목표) |
|---|---|
| 지표 정의 확정 절차, KPI 사전, SQL 검증 흐름 | 자체 LLM 학습·파인튜닝 |
| 샘플 주문 데이터(합성)로 하는 PoC | 실제 고객 데이터 사용 |
| 정의서와 리포트 md 자동 생성 | 대시보드 시각화 완성도 |

## 6. 두 공고와의 연결

| 공고 요구 | 이 문제에서 보여 줄 수 있는 것 |
|---|---|
| AI-BI: KPI 정의, SQL 로직, 시스템 프롬프트, RAG 튜닝 | KPI 사전을 RAG로 붙인 Text-to-SQL과 일치율 측정 |
| AI-BI: 현업·IT 커뮤니케이션 | 되묻기 질문 양식(요구 구조화) |
| R&D: PoC 설계·검증·문서화 | 성공 기준 합의 → 검증 → 리포트 |
| R&D: 오류·로그 기반 원인 분석 | 틀린 SQL 케이스의 원인 기록 |
